1. Resumen ejecutivo

Playdoit Monitor es un sistema automatizado que recolecta, normaliza, almacena y analiza los momios de eventos deportivos en vivo publicados en Playdoit.mx, entregando los resultados mediante un bot interactivo de Telegram. El sistema consume directamente la API JSON del proveedor del sportsbook (Altenar), lo que permite ciclos completos de recolección en aproximadamente siete segundos, sin necesidad de un navegador automatizado, con mayor estabilidad y con los momios entregados nativamente en formato decimal.

Además de los listados ordenados por momio, el sistema incorpora un algoritmo de índice de confianza que combina la probabilidad implícita depurada del margen de la casa, el avance del juego, la situación del marcador interpretada según el tipo de mercado y la tendencia histórica de la línea, así como un módulo de backtesting que registra y liquida automáticamente las selecciones emitidas para medir su tasa de acierto real.

Aviso legal. Este sistema consume de forma automatizada la API del sportsbook utilizado por Playdoit.mx, lo cual puede contravenir los términos de servicio del sitio. Su uso es bajo responsabilidad del operador, con intervalos de consulta moderados. Este documento y el sistema descrito no constituyen consejo de apuestas ni garantía de resultados.

2. Arquitectura general

El sistema se organiza en seis capas desacopladas, cada una implementada en un módulo independiente:

CapaMóduloResponsabilidad
Recolecciónsrc/fetcher.jsDescarga el panorama en vivo de todos los deportes desde la API de Altenar, con reintentos con retroceso exponencial y pausa de 500 ms entre deportes.
Normalizaciónsrc/normalize.jsAplana la estructura eventos–mercados–momios a filas homogéneas; calcula el momio americano, la probabilidad justa sin margen, el minuto de juego y el número de set.
Almacenamientosrc/db.jsBase SQLite (snapshots.db) con las tablas snapshots (histórico de momios) y picks (registro y liquidación de selecciones).
Análisissrc/analyze.js, src/confidence.js, src/markets.jsOrdenamiento por momio con filtros, algoritmo de índice de confianza y motor de interpretación y calificación de mercados.
Orquestaciónbot.jsBot de Telegram por long-polling, recolector de fondo periódico y liquidación automática de picks.
Notificaciónsrc/telegram.jsComposición y envío de mensajes HTML a través de la API de Telegram, restringido a un único chat autorizado.

Existe además un modo alternativo (index.js) que envía el top de jugadas por intervalos fijos de tiempo, útil como respaldo o para pruebas con la opción --once.

3. Fuente de datos

Durante la fase de exploración se identificó que Playdoit.mx opera su sección deportiva mediante el proveedor Altenar, cuyo frontend consulta la API pública sb2frontend-altenar2.biahosted.com. El sistema replica dichas consultas con los encabezados apropiados (User-Agent de navegador, Referer y Origin del sitio), utilizando el endpoint GetLiveOverview de manera global para enumerar los deportes activos y de manera individual por deporte para obtener eventos, mercados, momios, marcadores y minuto o parte en curso.

Este enfoque sustituye el raspado del DOM con navegador sin cabeza, reduciendo el tiempo de ciclo de decenas de segundos a aproximadamente siete, eliminando la fragilidad ante cambios visuales del sitio y entregando los momios ya en formato decimal.

6. Algoritmo de índice de confianza

Cada jugada candidata, con momio decimal entre 1.05 y 3.00, recibe un índice de confianza en el intervalo [0, 1] calculado como combinación ponderada de cuatro factores:

conf = 0.45·probJusta + 0.20·avance + 0.20·situación + 0.15·línea
FactorPesoMétodo de cálculo
Probabilidad justa45%Probabilidad implícita del momio normalizada dentro de su mercado, (1/momio) / Σ(1/momios), eliminando así el margen de la casa (vig), que infla las probabilidades entre cinco y ocho puntos porcentuales.
Avance del juego20%Proporción del juego transcurrido: minuto entre duración reglamentaria, o set actual entre sets totales, con parámetros específicos por deporte. A menor tiempo restante, mayor certeza del estado actual.
Situación del juego20%Evaluación del marcador actual interpretada según el tipo de mercado de la selección (véase la sección 6.1).
Tendencia de línea15%Sobre todos los snapshots de la última hora: pendiente relativa del momio (línea descendente indica mayor confianza del mercado) menos una penalización por volatilidad (línea oscilante indica incertidumbre).

7. Backtesting y medición de desempeño

Cada ejecución del comando /seguras registra sus selecciones en la tabla picks, incluyendo momio, índice de confianza y marca de tiempo. El recolector de fondo detecta cuándo un evento abandona el listado en vivo y procede a liquidar automáticamente las selecciones pendientes: el módulo de mercados califica cada pick como acierto o fallo contra el último marcador conocido del evento. El comando /stats presenta la tasa de acierto agregada por nivel de confianza (alta: 75% o más; media: 60–75%; baja: menos de 60%), permitiendo verificar la calibración de los pesos del algoritmo con datos reales.

Limitación conocida. La liquidación emplea el último marcador muestreado por el recolector (cada tres minutos por defecto) y no el resultado oficial del encuentro, por lo que en finales muy cerrados el resultado registrado puede diferir del real. Las selecciones no calificables se marcan como unknown y quedan excluidas de las estadísticas.

8. Modelo de datos

8.1 Tabla snapshots

Registra una fila por momio observado en cada ciclo de recolección:

ts, sport, sport_id, champ, event_id, event, score, live_time,
market, selection, odd_decimal, odd_american

8.2 Tabla picks

Registra las selecciones emitidas por /seguras y su liquidación:

ts, event_id, event, sport, market, selection, odd_decimal, conf,
result, final_score, settled_ts

8.3 Consultas de referencia

-- Movimiento de línea de un evento
SELECT ts, market, selection, odd_decimal FROM snapshots
WHERE event_id = 16838147 ORDER BY ts;

-- Historial de picks liquidados
SELECT ts, event, selection, odd_decimal, conf, result, final_score
FROM picks WHERE result IS NOT NULL ORDER BY ts DESC;

9. Consideraciones operativas

El bot permanece activo mientras su proceso siga en ejecución; para operación permanente se recomienda configurarlo como tarea programada de Windows o como servicio. Las consultas a la API se realizan con encabezados de navegador legítimos, pausa de 500 ms entre deportes y reintentos con retroceso ante fallos, a fin de mantener una huella de tráfico moderada. El bot únicamente atiende mensajes provenientes del chat autorizado en la configuración, descartando cualquier otro origen. Finalmente, la calidad del factor de tendencia de línea es proporcional al historial acumulado: el recolector de fondo alimenta la base de datos cada tres minutos incluso sin actividad del usuario.
